# 技術制約

デザインは最終的に **Astro 6 の静的サイト**に移植される。
移植する人間（エンジニア）がそのまま使えるよう、以下を守ってほしい。

---

## 1. 成果物の形

| 欲しいもの | 形式 |
|---|---|
| デザイントークン | **`tokens.css` の差し替え版**（変数名は下の契約を守る） |
| 各ページ・図表の設計 | **素の HTML + CSS**（1ファイル完結でよい） |
| 動きのあるもの | **バニラ JS**。ライブラリは使わない |

React・Vue・Svelte・Tailwind・jQuery は使わないでほしい。
Astro コンポーネントに手で移植するので、素の HTML/CSS が最も移植しやすい。

---

## 2. トークン契約 — これを壊さない

`現状コード/tokens.css` が現行の全変数。**既存の変数名は消さず、値だけを変える**。
新しい変数を足すのは自由。全ページ・全コンポーネントがこの名前を参照している。

### 面と文字
```
--paper --paper-2 --paper-3 --card
--ink --ink-2 --ink-3 --ink-4
--rule --rule-2
--navy --shadow --shadow-lg
```

### 時代の色（8期）— `periods.ts` と対応
```
--c-shoni --c-ryuzoji --c-seiritsu --c-kakuritsu
--c-mosaku --c-naomasa --c-ishin --c-yoha
```

### 主題の色（6系統）— `themes.ts` と対応
```
--t-seido --t-kashin --t-zaisei --t-gunji --t-sangyo --t-bunka
```

### そのページのアクセント
```
--era        時代／主題に応じて body に差し込まれる
--era-soft   上記の薄い版
```

### 信頼度バッジ
```
--conf-sourced-fg --conf-sourced-bg
--conf-ai-fg      --conf-ai-bg
--conf-note-fg    --conf-note-bg
```

### 書体・寸法・動き
```
--f-mincho --f-sans --f-en --f-mono
--fs-xs --fs-sm --fs-base --fs-body --fs-lg --fs-h2 --fs-h1 --fs-hero
--leading-body --measure
--w-wide --w-narrow --gutter
--ease-out --dur --cue --cue-step
```

**色の設計で注意**：時代8色と主題6色が同じ画面に同時に出る場面が多い
（マトリクス、記事カード、年表）。14色が喧嘩しないこと。
時代は「時間の並び」なので順序が感じられる並びが望ましく、
主題は「並立するカテゴリ」なので順序を感じさせない方がよい。

---

## 3. ライトとダークの両対応（必須）

`:root` がライト、`:root[data-theme="dark"]` がダーク。
ダークは「墨と行灯の火」という方向で作られているが、変えてよい。

**両方で成立しない設計は採用できない。** とくに図表。
透明度だけで階層を表す図はダークで潰れることが多い。

---

## 4. パフォーマンス予算

| ページ | JavaScript |
|---|---|
| 記事ページ | **0KB**（ルーターを除く） |
| 図表のあるページ | 100KB 以下（gzip） |

- 図表は**可能な限りビルド時に SVG として吐く**。現に知行高グラフはそうしている
- 動きが必要な場合のみ、そのページにだけ JS を置く
- LCP 2.0秒以下、CLS 0.1以下
- 画像は AVIF/WebP・遅延読み込み。**ただし現時点で写真は0点**

---

## 5. アクセシビリティ

- `prefers-reduced-motion: reduce` で**すべてのアニメーションを止める**。
  動きが情報を伝えている図は、静止状態でも同じ情報が読めること
- 図表には必ず代替テキスト、または同じ内容の表を併置する
- 色だけで意味を区別しない（時代・主題・信頼度すべて）
- キーボードだけで全機能に到達できること。
  現状のマトリクスや探索UIは、マウスなしでも動くように作ってある
- コントラスト比 4.5:1 以上（本文）

---

## 6. JavaScript 無効でも壊れない

現状、マトリクスも画像探索UIも年表の絞り込みも、
**JS 無効時は全件が一覧として読める**ように作ってある。この性質は保ってほしい。

```
JS なし … すべての中身が展開された状態で読める
JS あり … 選んだものだけが表示され、その場で切り替わる
```

---

## 7. レスポンシブ

- 最小 **360px** まで破綻しないこと
- 横スクロールが出てよいのは、表・図・コードブロックだけ（各自 `overflow-x: auto` の中）
- ページ本体が横スクロールしてはいけない
- **狭い画面で情報を消して逃げない**。現状の年表は狭い画面で和暦を
  `display: none` にしているが、これは逃げ。別の畳み方を設計してほしい

---

## 8. 書体

現在 Google Fonts から以下を読んでいる。変更してよいが、
**日本語の明朝とゴシックは必須**（本文は長く、縦の密度が高い）。

| 変数 | 現在 |
|---|---|
| `--f-mincho` | Shippori Mincho B1（見出し・本文の要所） |
| `--f-sans` | Zen Kaku Gothic New（UI・本文） |
| `--f-en` | Cormorant Garamond（欧文） |
| `--f-mono` | JetBrains Mono（年号・数値・ラベル） |

**年号と石高が至るところに出る**ので、数字の見え方は重要。
現在は等幅にして「データである」ことを示している。

---

## 9. 作らなくてよいもの

- ヘッダー・フッター・検索ページ（そのまま使う）
- 記事本文の組版（`prose` は既に作り込んである。ただし課題3の幅の問題は直す）
- 出典欄の書式（自動生成されている）
