## 依頼

### 第1段階 — デザインの方向を決める

まず `tokens.css` の差し替え版を作ってほしい。
色・書体・寸法・余白・動きの体系。`05-技術制約.md` の変数名の契約を守ること。

あわせて、**なぜその方向にしたのか**を数行で説明してほしい。
この題材（武家の制度・身分・軍制）に、なぜその色と書体が合うのか。

方向が固まってから次へ進む。いきなり全ページ作り込まないでほしい。

### 第2段階 — 最重要の2つの図を作る

`01-課題リスト.md` の課題9。**職制図**と**家格ピラミッド**。

この2つはサイト全体の図表の水準を決める見本になる。
ここに最も力を入れてほしい。データは `04-実データ.md` にすべてある。

それぞれ、こういう構造が**図そのもので**伝わることを目指す。

- **職制図**：役方（行政）と番方（軍事）が並立していること。
  役方は請役所を頂点とする階層であること。
  文書行政（案文方）が独立した機能として組み込まれていること
- **家格ピラミッド**：三家から足軽まで11段の身分差。
  同時に、**これは本藩から見た序列にすぎず、三支藩・親類・親類同格は
  独自の職制を別に持っていた**という留保。
  つまり「単一のピラミッドではない」ことがこの図の要点

### 第3段階 — 残りのページ

課題 1・2・3・5・6・7・8。
それぞれ HTML + CSS（必要ならバニラ JS）で、1ファイル完結のモックアップを。

## 守ってほしいこと

1. **実データを使う。** `04-実データ.md` の文字列をそのまま入れる。
   日本語の実際の字数・固有名詞の長さが、レイアウトの成否を決める
2. **ライトとダーク両方で成立させる。** 片方だけのデザインは採用できない
3. **素の HTML/CSS/バニラ JS で作る。** React・Tailwind・jQuery は使わない。
   Astro コンポーネントに手で移植するため
4. **JavaScript 無効でも中身が読めること。** JS は強化であって前提ではない
5. **360px まで破綻しないこと。** 狭い画面で情報を `display:none` で
   消して逃げないこと
6. **欠損を隠さない。** 記事のないマス、座標のない地名、記録のない年が
   実際にある。推定で埋めることは運営方針で禁じられている。
   **欠けていることを、みすぼらしくなく見せる**のが設計の課題

## いちばん難しいところ

このサイトには**写真が1枚もない**。当面それは変わらない。

参照先の「まつりと」は写真が主役のサイトで、そのままは真似できない。
**写真なしで、図と文字だけで、密度が高く美しい画面をどう作るか。**
ここが今回の中心的な問いだと考えてほしい。

あわせて、記事はいま**5本しかない**が、目標は115本。
**5本でもスカスカに見えず、115本でも破綻しない**設計が要る。

## 題材について

佐賀藩は、旧主家（龍造寺氏）の一門を「親類同格」として抱え込み、
**藩政の最高責任者をその旧主家一門から交代で出させた**という変則的な構造を持つ。
借銀が収入の過半を占める赤字財政を、削られた側の家に運営させる配置だった。

長崎警備を福岡藩と一年交代で担い、有明海を干拓して石高を伸ばし、
幕末には反射炉とアームストロング砲を持つ技術先進藩になった。

**制度と構造の話が中心**であって、合戦や英雄譚のサイトではない。
軽薄な装飾もポップな配色も合わないが、古めかしい「和風テンプレート」も違う。
現代的で、硬質で、密度が高く、それでいて読みやすい——という線を狙ってほしい。
