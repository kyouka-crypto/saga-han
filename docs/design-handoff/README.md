# Claude design 引き継ぎ資料

デザインを Claude design で作り直すために、渡すものを一式まとめたフォルダ。

## 使い方

Claude Design の画面には Slides / Design / Design in codebase / Design System の
4つがある。使うのは **Design System** と **Design** の2つ。

| 順 | 選ぶもの | 貼るプロンプト | 得るもの |
|---|---|---|---|
| ① | **Design System** | `PROMPT-1-デザインシステム.md` | `tokens.css` の差し替え版と基本部品 |
| ② | **Design** | `PROMPT-2-図表.md` | 職制図・家格ピラミッド（図表の水準の見本） |
| ③ | **Design** | `PROMPT-3-各ページ.md` の A〜F を**1つずつ** | 各ページの設計 |

**いきなり全部を頼まない。** 1回のやりとりで複数ページを頼むと出力が散漫になる。
③は A〜F を別々の会話として依頼する。

添付できるなら、各プロンプトの冒頭に書いてあるファイルを添付する。
添付できなくてもプロンプト単体で成立するように書いてある。

出てきた成果物はこのフォルダに戻す。VSCode 側で Astro へ移植する。

### Design in codebase を使わない理由

リポジトリを直接触るモードだが、このプロジェクトは制約が特殊
（記事ページ JS 0KB、ライブラリ禁止、JS 無効でも全件読める、
ライト／ダーク両対応、トークン変数名の契約）。
コードベース側で自動生成されると、制約を踏んだかどうかの検証が差分レビューになって重い。
**独立した HTML/CSS で受け取って移植する方が、制約違反を確実に潰せる。**

ただし実際に動かして確かめたわけではない。試すなら①で方向が固まった後に。

| # | 内容 | 重さ |
|---|---|---|
| 1 | 全体が単調。四角形が多すぎる | ★ |
| 2 | 俯瞰マトリクスが数値表にすぎない | ★★ |
| 3 | 記事本文の横幅が狭すぎる（目次と欄外注は残す） | |
| 4 | 不適切な出典の削除 → **対応済み。設計対象外** | |
| 5 | トップの年表（1200–1877）がだめ | ★ |
| 6 | 「家と家格」ページがだめ | ★★ |
| 7 | 年表がテキストだけ。2〜3項目ごとに図版を | |
| 8 | 「人物と家」を索引に徹させ、家ごとの詳細ページ＋地図へ | ★★ |
| 9 | 職制図と家格ピラミッドを作り直す（図表の水準の見本） | ★★ |
